# تطبيق حِدمتي — أندرويد (غلاف WebView)

مشروع Android Studio كامل وجاهز — يخدم لوحتَي **العميل والمزوّد معاً** (نفس الموقع يفرّق بينهما حسب تسجيل الدخول).

## 🧪 وضع التجربة الحالي (debug) — مضبوط مسبقاً على شبكتك المحلية

`BASE_URL` بوضع debug مضبوط حالياً على `http://192.168.1.32:3000/` (خادم Vite بجهازك). هذا يشتغل **فقط** لما جوالك على نفس شبكة الواي-فاي بالضبط لجهازك — طبيعي لمرحلة التجربة، لكن **لن يعمل** بعد نشر حقيقي (يحتاج الرابط النهائي https).

لو تغيّر عنوان جهازك لاحقاً (شبكة مختلفة، إعادة تشغيل الراوتر أحياناً)، حدِّث نفس الـIP بمكانين معاً:
1. `app/build.gradle.kts` (سطر `debug { buildConfigField(...) }`)
2. `app/src/main/res/xml/network_security_config_debug.xml` (سطر `<domain>`)

هذا الاستثناء (`http://` بدل `https://`) **يُطبَّق فقط على نسخة debug** — نسخة `release` (اللي تُنشَر فعلياً) تبقى `https` إلزامية بلا أي استثناء، محمية تماماً.

## ⚠️ الخطوة الإلزامية قبل النشر الفعلي (release)

افتح `app/build.gradle.kts` وعدِّل السطر:
```kotlin
buildConfigField("String", "BASE_URL", "\"https://hidmaty.example.com/\"")
```
غيّره لعنوان موقعك الفعلي المنشور (يجب يكون `https://` — لن يعمل بـ`http://` لأن `usesCleartextTraffic=false` بالبيان لأسباب أمنية).

يوجد سطران بنفس الملف (`release` و`debug`) — عدِّل الاثنين لنفس الرابط (أو اجعل `debug` يشير لبيئة اختبار منفصلة لو عندك واحدة).

## 🤖 بناء تلقائي بلا تثبيت أي برنامج (GitHub Actions)

المشروع يحتوي `.github/workflows/build-apk.yml` جاهز. الخطوات:
1. أنشئ مستودع (repository) جديد بحساب GitHub (مجاني)
2. ارفع محتوى هذا المجلد كامل له
3. افتح تبويب **Actions** بالمستودع — البناء يبدأ تلقائياً (يأخذ 2-4 دقائق)
4. لما ينتهي (علامة ✅ خضراء)، افتح الـرن نفسه → أسفل الصفحة قسم **Artifacts** → حمّل `hidmaty-app-debug` (ملف مضغوط يحتوي الـAPK بداخله)
5. انقله لجوالك وثبّته (فعِّل "مصادر غير معروفة" بإعدادات الجوال أول مرة)

⚠️ هذا يبني نسخة **debug** (تشير حالياً لـ`http://192.168.1.32:3000/`) — تعمل فقط لما جوالك على نفس شبكتك المحلية وخادم التطوير شغّال.

## خطوات التشغيل

1. حمِّل [Android Studio](https://developer.android.com/studio) (مجاني)
2. افتح المجلد الكامل لهذا المشروع (File → Open)
3. انتظر Gradle يُحمِّل التبعيات أول مرة (يحتاج إنترنت، دقيقة أو دقيقتين)
4. اضغط زر التشغيل (▶) لتجربته على محاكي أو جهاز حقيقي موصول بالـUSB

## لبناء ملف APK جاهز للتوزيع

**Build → Generate Signed Bundle / APK → APK** — أنشئ مفتاح توقيع جديد (Keystore) أول مرة واحفظه بمكان آمن (تحتاجه لكل تحديث مستقبلي، ولا يمكن استرجاعه لو ضاع).

للنشر على **Google Play** تحديداً، اختر **Android App Bundle (.aab)** بدل APK — Play Store يطلبه بهذا الشكل.

## ما يحتاج انتباهك قبل النشر الفعلي

### 1) الأيقونة
الأيقونة الحالية **دائرة ذهبية بسيطة placeholder** (`res/drawable/ic_launcher_*.xml`) — استبدلها بشعارك الحقيقي:
- أسهل طريقة: بـAndroid Studio، كليك يمين على `res` → New → Image Asset → اختر صورة شعارك بصيغة PNG بخلفية شفافة

### 2) الإشعارات (Push Notifications)
هذا المشروع **لا يشمل** إشعارات فورية (Firebase Cloud Messaging) — الموقع نفسه يعرض إشعاراته لما المستخدم يفتح التطبيق فقط، لا تصل إشعار للجهاز وهو مغلق. لو تحتاجها لاحقاً:
- أنشئ مشروع Firebase مجاني
- أضف `google-services.json` للمشروع
- أضف مكتبة `firebase-messaging`، واربط توكن الجهاز بباك-إند حِدمتي لإرسال الإشعارات

### 3) رفع الصور
مُختبَر ومدعوم بالكامل — اختيار من المعرض **أو** التقاط كاميرا مباشرة (كلاهما بنفس الحوار). لو صادفت مشكلة برفع صورة معيّنة، الأرجح السبب إعداد `<input>` بصفحة الويب نفسها (`accept="image/*"` مثلاً)، لا الكود الأندرويدي.

### 4) الموقع الجغرافي
الموقع سيطلب صلاحية الموقع تلقائياً أول ما يفتح المستخدم صفحة فيها خريطة — لا حاجة لأي إعداد إضافي.

### 5) اسم الحزمة (Package Name)
حالياً `com.hidmaty.app` — **لا يمكن تغييره بعد أول نشر على Google Play** (يصبح هوية دائمة للتطبيق). راجعه جيداً بـ`app/build.gradle.kts` (`applicationId`) قبل أول نشر رسمي.

## هيكل المشروع (للمرجعية)

```
app/src/main/
├── AndroidManifest.xml          الصلاحيات والأنشطة
├── java/com/hidmaty/app/
│   ├── HidmatyApp.kt             فئة التطبيق
│   ├── SplashActivity.kt         شاشة البداية
│   └── MainActivity.kt           المنطق الكامل (WebView، رفع صور، موقع، إلخ)
└── res/
    ├── layout/activity_main.xml  التخطيط
    ├── values/colors.xml         ألوان الهوية (مطابقة لموقعك)
    ├── values/strings.xml        النصوص
    ├── values/themes.xml         السمة + شاشة البداية
    └── drawable + mipmap/        الأيقونة (placeholder، استبدلها)
```

## أسئلة شائعة

**س: تسجيل الدخول ما يستمر، يطلب مني الدخول كل مرة أفتح التطبيق؟**
تحقّق أن موقعك يحفظ الجلسة بكوكيز عادية (لا `sessionStorage` وحدها) — الكود هنا يفعّل الكوكيز بشكل صحيح (`CookieManager`)، لكن لو الباك-إند يعتمد آلية جلسة غير قياسية، يحتاج تحقّقاً إضافياً.

**س: أقدر أضيف اسمين مختلفين للتطبيق (عميل/مزوّد) بمتجرَين منفصلين؟**
نعم ممكن لاحقاً — تُنسَخ الفئة `app` لموديولين بنفس الكود لكن `applicationId`/الاسم/الأيقونة مختلفين، وكل واحد يفتح على نفس `BASE_URL` (الموقع نفسه يفرّق حسب تسجيل الدخول كما هو الآن). غير ضروري الآن بما إن تطبيقاً واحداً يخدم الاثنين تلقائياً.
